# vuln-strategy-analyzer 设计文档

## 概述

vuln-strategy-analyzer 是一个智能漏洞测试策略分析 skill，根据用户的自然语言任务描述，自动识别输入形态、分类任务意图、选择方法论、生成详细的执行步骤计划。**只出计划，不执行**——产物是结构化的策略计划文件，供用户确认后手动执行或交给其他工具实施。

## 触发方式

- **显式调用（on-demand）**：用户必须明确提及本 skill 的名称才能触发
- 不自动响应任何关键词

## 架构：四层分层融合

```
用户输入
   ↓
Layer 1: 输入形态识别
   ↓
Layer 2: 任务意图分类
   ↓
Layer 3: 方法论选择
   ↓
Layer 4: 场景细化 + 执行步骤生成
   ↓
输出到 .vuln_strategy/{slug}-{MMDD-HHMMSS}.md
```

### Layer 1：输入形态识别

自动检测用户提供的输入属于哪种形态。检测策略：**扩展名判断 + 模糊时反问**。

| 形态 | 判断依据 | 示例 |
|---|---|---|
| 代码目录 | 路径是目录，或路径存在但非标准源码/报告扩展名 | `/src`、`.`、`/home/user/project` |
| 源码文件 | 扩展名为 `.java/.py/.php/.js/.go/.ts/.c/.cpp/.rb/.kt/.swift` 等 | `UserController.java` |
| 扫描报告 | 扩展名为 `.json/.sarif/.html/.xml` 且内容结构符合扫描工具输出 | `xray-report.json`、`results.sarif` |
| REST 接口 | 含 HTTP method + path 模式（GET/POST/PUT/DELETE + /path） | `GET /api/order`、`/api/order/delete` |
| URL | 以 `http://` 或 `https://` 开头 | `https://example.com` |
| 日志/其他 | 无法自动识别 → 反问用户 | `app.log`、`error.log` |
| 纯文本描述 | 没有路径/URL/接口，只有自然语言描述 | "帮我看看这个登录接口" |

### Layer 2：任务意图分类

根据输入形态 + 用户自然语言将任务归入以下类别：

| 意图分类 | 触发条件 | 示例用户输入 |
|---|---|---|
| FULL_AUDIT（全量审计） | 只给目录，未指定漏洞类型 | "审计一下这个 /src 目录" |
| TARGETED_AUDIT（定向审计） | 目录/文件 + 指定了漏洞类型 | "找找 SQL 注入"、"查一下 XSS" |
| SCAN_TRIAGE（二次确认） | 给了扫描报告 | "帮我看下这个 Xray 报告"、"Semgrep 报了 3 个 RCE" |
| ENTRY_ANALYSIS（入口分析） | 给了 REST 接口/函数名 | "分析 /api/order/delete"、"看 resetPassword 方法" |
| VULN_VERIFICATION（漏洞验证） | 指定参数/代码位置 | "这个参数 id 可能有 SQL 注入" |
| PATCH_REVIEW（补丁验证） | 给了 diff/patch | "看看这个补丁有没有绕过" |
| BLACK_BOX（黑盒） | 只给了 URL 无源码 | "这个网站帮我挖挖漏洞" |
| LOG_ANALYSIS（日志推测） | 给了日志文件 | "这份日志有很多 500 错误" |
| MIXED（混合/模糊） | 覆盖多个方向 | "帮我测测这个登录接口" |
| UNKNOWN（无法识别） | 完全无法判断 | → 反问用户 |

### Layer 3：方法论选择

| 意图分类 | 推荐方法论 | 核心策略 |
|---|---|---|
| FULL_AUDIT | 混合（交汇验证） | 先自顶向下枚举入口，再自底向上补高价值 sink，交叉核对 |
| TARGETED_AUDIT | 按漏洞类型决定 | SQL/命令/反序列化→自底向上；越权/逻辑→自顶向下；敏感信息→通用 |
| SCAN_TRIAGE | 自底向上（sink 驱动） | 从每个上报的 sink 反向溯源，确认或证伪可达性 |
| ENTRY_ANALYSIS | 自顶向下（入口驱动） | 穷举入口的所有输入，正向追踪危险操作 |
| VULN_VERIFICATION | 视情况 | 给 sink→自底向上；给入口→自顶向下；给代码行→双向 |
| PATCH_REVIEW | 差异对比+绕过分析 | 对比修复前后代码，判断修补是否完整可绕过 |
| BLACK_BOX | 通用黑盒方法论 | 按 OWASP Top 10 枚举测试 |
| LOG_ANALYSIS | 异常驱动回溯 | 分析异常栈→定位代码→判定是否漏洞 |
| MIXED | 多方向并行 | 列出所有方向按优先级排序 |
| UNKNOWN | 反问+通用 | 反问澄清；无法澄清默认 FULL_AUDIT |

### Layer 4：场景细化与执行步骤

内置预定义场景库，按 Layer 1+2+3 的结果匹配最接近的场景模板，输出细化执行步骤。

主要场景模板：

1. **FULL_AUDIT + 目录** → 三阶段：暴露面收集 → 危险点扫描 → 交叉验证
2. **TARGETED_AUDIT + 目录 + 注入类** → 自底向上：grep sink → 追溯 source → 检查清洗
3. **TARGETED_AUDIT + 目录 + 逻辑漏洞** → 自顶向下：枚举入口 → 分析权限 → 检查越权
4. **TARGETED_AUDIT + 目录 + 敏感信息** → 通用：grep 敏感模式 → 验证可达性
5. **SCAN_TRIAGE + 报告** → 逐个 finding：读取 → 追溯 → 确认/证伪
6. **ENTRY_ANALYSIS + REST接口** → 输入梳理 → 数据流追踪 → 逐类检查漏洞
7. **ENTRY_ANALYSIS + 函数名** → 分析调用链 → 正向追踪 → 检查校验
8. **VULN_VERIFICATION + 具体位置** → 定位代码 → 三问分析
9. **PATCH_REVIEW + diff** → 对比修复前后 → 检查绕过路径
10. **MIXED/模糊** → 列出所有可能方向，标注优先级

未匹配到预定义场景 → fallback 到通用决策树生成步骤。

## 方法论参考

### 自顶向下（入口驱动，正向污点）

1. 梳理入口的全部输入——参数、header、body 字段、query string、cookie
2. 沿着每个被污染的值正向追踪，区分保留污点和中和污点的变换
3. 标记到达 sink 的污点值
4. 对每个标记确认攻击者能否触发并绕过清洗

### 自底向上（sink 驱动，反向可达性）

1. 获取 sink 清单（工具报告或 grep）
2. 对每个 sink，反向沿调用图追溯参数来源
3. 追溯到不可信源 → 确认；硬编码值 → 误报；断链 → 疑似
4. 检查路径上是否有清洗逻辑可被绕过

### 混合（交汇验证）

1. 先自顶向下覆盖暴露面最大的入口
2. 再自底向上扫高价值 sink
3. 交叉核对两方向的结果

## 输出产物

### 目录

`.vuln_strategy/`——独立的隐藏目录，位于被分析项目的根目录下。

### 文件名

`strategy-{slug}-{MMDD-HHMMSS}.md`

- `{slug}`：简短英文标识，小写字母+连字符，从用户任务中提取
- `{MMDD-HHMMSS}`：生成时间戳（如 `0612-143022`）

### 文件内容结构（A-F 六大板块）

## 场景任务方法指引

### 代码审计类

- **给定目录未指定漏洞类型** → 混合方法论：先自顶向下枚举入口，再自底向上扫高价值 sink
- **给定目录+指定漏洞类型（SQL/命令/反序列化）** → 自底向上：grep 对应 sink → 反向追溯
- **给定目录+指定漏洞类型（越权/逻辑/XSS）** → 自顶向下：枚举入口 → 追踪数据流
- **给定目录+指定漏洞类型（敏感信息泄露）** → 通用方法论：grep 敏感模式 + 验证可达性
- **给定单个文件** → 按文件内容判断：入口类→自顶向下；工具类→自底向上

### 扫描结果二次确认类

- 统一用**自底向上**方法论
- 对每个上报的 finding，从 sink 出发反向追溯到 source
- 能追溯且无有效清洗 → 确认漏洞
- 无法追溯或硬编码 → 判定误报
- 调用链中断或动态分发 → 标记为疑似

### 入口函数分析类

- 统一用**自顶向下**方法论
- REST 接口：先看框架路由注册→梳理所有输入→正向跟踪每个输入
- 函数名：分析函数签名→查看调用者传递的实参→检查校验逻辑
- 覆盖常见检查：认证缺失、鉴权缺陷、参数校验不严、返回信息过多

### 混合/模糊任务

- 列出所有可能的测试方向
- 按风险等级排序优先级
- 每个方向标注推荐方法论

### 特定漏洞类型直接提问

- 按漏洞类型映射到对应方法论：
  - SQL 注入 / 命令注入 / 反序列化 → 自底向上
  - SSRF / 文件上传 / 目录穿越 → 自顶向下
  - 越权 / IDOR → 自顶向下（关注权限验证）
  - JWT / 认证逻辑 → 自顶向下（关注解析和校验）

## 不自包含原则

本 skill **只输出策略计划**，不执行以下操作：
- 不读源码分析漏洞
- 不调用其他 skill
- 不写 `.vuln_agent_output/` 下的任何文件
- 不修改被分析项目的任何文件

## 完整工作流程

1. 用户显式调用 `vuln-strategy-analyzer`
2. 读取用户消息，提取输入和意图
3. **Layer 1**：识别输入形态（扩展名判断 + 模糊反问）
4. **Layer 2**：归入意图分类
5. **Layer 3**：选择方法论并说明理由
6. **Layer 4**：匹配场景模板 → 生成详细执行步骤（未匹配→fallback 通用决策树）
7. 组装 A-F 六大板块
8. 写入 `.vuln_strategy/strategy-{slug}-{MMDD-HHMMSS}.md`
9. 对话中摘要告知用户产物路径和核心建议
