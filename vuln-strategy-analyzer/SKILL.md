# vuln-strategy-analyzer

## 定位

先识别用户意图（审计/二次确认/入口分析/...），再根据意图分析输入和任务范围，推荐方法论，生成策略计划。只出计划，不执行。产物是 `.vuln_strategy/strategy-{slug}-{MMDD-HHMMSS}.md`。

## 意图与任务分析

从用户消息中识别意图，再匹配输入形态和任务范围，映射方法论：

| 意图分类 | 典型输入 | 方法论 |
|---|---|---|
| FULL_AUDIT（全量审计） | 目录，未指定漏洞类型 | 混合（自顶向下+自底向上） |
| TARGETED_AUDIT（定向审计） | 目录/文件 + 指定漏洞类型 | 注入类→自底向上；逻辑类→自顶向下；敏感信息→通用 |
| SCAN_TRIAGE（二次确认） | 扫描报告（.sarif/.json/.html） | 自底向上（反向溯源） |
| ENTRY_ANALYSIS（入口分析） | REST 接口 / 函数名 | 自顶向下（入口驱动） |
| VULN_VERIFICATION（漏洞验证） | 指定参数/代码行 | 按 sink 或入口选方向 |
| PATCH_REVIEW（补丁验证） | diff/patch | 差异对比+绕过分析 |
| BLACK_BOX（黑盒） | URL（无源码） | 通用黑盒 |
| LOG_ANALYSIS（日志推测） | 日志文件 | 异常驱动回溯 |
| MIXED（混合/模糊） | 覆盖多个方向 | 多方向并行列出 |
| UNKNOWN（无法识别） | - | 反问用户 |

## 执行步骤生成

按方法论决定通用步骤模式：

- **自顶向下**：梳理入口输入 → 正向污点追踪 → 标记到达 sink 的路径 → 检查清洗是否可绕过
- **自底向上**：定位 sink → 反向追溯 source → 判断可控性 → 检查清洗是否可绕过
- **混合**：先自顶向下覆盖主要入口，再自底向上补高价值 sink，交叉核对
- **通用黑盒**：按 OWASP Top 10 枚举测试

## 输出产物

`.vuln_strategy/strategy-{slug}-{MMDD-HHMMSS}.md`，六段结构：

```markdown
# 漏洞分析策略计划

## A. 任务分类
- **意图分类**：<FULL_AUDIT | TARGETED_AUDIT | ...>
- **输入形态**：<目录 | 源码文件 | 扫描报告 | ...>
- **原始任务**：<用户消息摘录>

## B. 输入形态识别
- **识别结果**：<如 /path/to/src 是一个 Java Maven 项目>
- **分析目标**：<一句话描述>

## C. 推荐方法论
- **方法论**：<自顶向下 | 自底向上 | 混合 | ...>
- **选择理由**：<一句话解释>

## D. 执行步骤
1. 第一步
2. 第二步
3. ...

## E. 建议关注的漏洞类型
- <主要类型>（重点关注）

## F. 范围约束
- **范围内**：<覆盖范围>
- **范围外**：<不覆盖内容>
- **假设**：<分析前提>
```

## 原则

- **只出计划，不执行**：不读源码、不调其他 skill、不改被分析项目
- **反问克制**：仅输入形态无法判断、意图无法识别时才反问；MIXED 不反问
- **路径真实**：路径存在时先验证它实际是什么
- **诚实标注**：在 F 区明确标注假设和范围外内容
