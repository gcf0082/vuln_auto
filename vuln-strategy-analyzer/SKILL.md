# vuln-strategy-analyzer

## 定位

分析用户漏洞挖掘任务 → 输出结构化策略计划。只出计划，不执行。产物是 `.vuln_strategy/strategy-{slug}-{MMDD-HHMMSS}.md`。

## 任务分析

输入形态 + 用户语言 → 意图分类 → 方法论映射：

| 输入形态 | 意图分类 | 方法论 |
|---|---|---|
| 目录（未指定漏洞类型） | FULL_AUDIT | 混合（自顶向下+自底向上） |
| 目录/文件 + 指定漏洞类型 | TARGETED_AUDIT | 注入类→自底向上；逻辑类→自顶向下；敏感信息→通用 |
| 扫描报告（.sarif/.json/.html） | SCAN_TRIAGE | 自底向上（反向溯源） |
| REST 接口 / 函数名 | ENTRY_ANALYSIS | 自顶向下（入口驱动） |
| 指定参数/代码行 | VULN_VERIFICATION | 按 sink 或入口选方向 |
| diff/patch | PATCH_REVIEW | 差异对比+绕过分析 |
| URL（无源码） | BLACK_BOX | 通用黑盒 |
| 日志文件 | LOG_ANALYSIS | 异常驱动回溯 |
| 覆盖多个方向 | MIXED | 多方向并行列出 |
| 无法识别 | UNKNOWN | 反问用户 |

## 执行步骤生成

按方法论决定通用步骤模式：

- **自顶向下**：梳理入口输入 → 正向污点追踪 → 标记到达 sink 的路径 → 检查清洗是否可绕过
- **自底向上**：定位 sink → 反向追溯 source → 判断可控性 → 检查清洗是否可绕过
- **混合**：先自顶向下覆盖主要入口，再自底向上补高价值 sink，交叉核对
- **通用黑盒**：按 OWASP Top 10 枚举测试

## 输出产物

`.vuln_strategy/strategy-{slug}-{MMDD-HHMMSS}.md`，六段结构：

```markdown
# 漏洞分析策略计划

## A. 任务分类
- **意图分类**：<FULL_AUDIT | TARGETED_AUDIT | ...>
- **输入形态**：<目录 | 源码文件 | 扫描报告 | ...>
- **原始任务**：<用户消息摘录>

## B. 输入形态识别
- **识别结果**：<如 /path/to/src 是一个 Java Maven 项目>
- **分析目标**：<一句话描述>

## C. 推荐方法论
- **方法论**：<自顶向下 | 自底向上 | 混合 | ...>
- **选择理由**：<一句话解释>

## D. 执行步骤
1. 第一步
2. 第二步
3. ...

## E. 建议关注的漏洞类型
- <主要类型>（重点关注）

## F. 范围约束
- **范围内**：<覆盖范围>
- **范围外**：<不覆盖内容>
- **假设**：<分析前提>
```

## 原则

- **只出计划，不执行**：不读源码、不调其他 skill、不改被分析项目
- **反问克制**：仅输入形态无法判断、意图无法识别时才反问；MIXED 不反问
- **路径真实**：路径存在时先验证它实际是什么
- **诚实标注**：在 F 区明确标注假设和范围外内容
