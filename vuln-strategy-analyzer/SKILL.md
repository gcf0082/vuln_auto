# vuln-strategy-analyzer

## 定位

识别用户任务特征 → 选择方法论 → 生成策略计划。只出计划，不执行。产物是 `.vuln_strategy/strategy-{slug}-{MMDD-HHMMSS}.md`。

## 任务分析

| 任务特征 | 方法论 | 参考 |
|---|---|---|
| 给了入口（接口/函数/路由/Controller，有源码） | 自顶向下 | `references/methodology/top-down.md` |
| 给了可疑操作/危险函数/扫描报告 finding（有源码） | 自底向上 | `references/methodology/bottom-up.md` |
| 给了特定分析逻辑（如"用正则扫密钥"、"检查 JWT 校验"） | 用户自定义 | — |
| 只给目录/项目，没说方向 | 混合（自顶向下+自底向上） | 两者 |
| 入口和可疑点都给了 | 双向，交叉验证 | 两者 |
| 只给 URL 无代码 / 模糊不清 | 反问用户补充（要源码/报告/入口？） | — |

## 输出产物

`.vuln_strategy/strategy-{slug}-{MMDD-HHMMSS}.md`，六段结构：

```markdown
# 漏洞分析策略计划

## A. 任务分类
- **意图分类**：<入口分析 | 二次确认 | 全量审计 | ...>
- **输入形态**：<目录 | 源码文件 | 扫描报告 | REST 接口 | ...>
- **原始任务**：<用户消息摘录>

## B. 输入形态识别
- **识别结果**：<如 /path/to/src 是一个 Java Maven 项目>
- **分析目标**：<一句话描述>

## C. 推荐方法论
- **方法论**：<自顶向下 | 自底向上 | 混合 | 用户自定义>
- **选择理由**：<一句话解释>

## D. 执行步骤
1. 第一步
2. 第二步
3. ...

## E. 建议关注的漏洞类型
- <主要类型>（重点关注）

## F. 范围约束
- **范围内**：<覆盖范围>
- **范围外**：<不覆盖内容>
- **假设**：<分析前提>
```

## 原则

- **只出计划，不执行**：不读源码、不调其他 skill、不改被分析项目
- **路径真实**：路径存在时先验证它实际是什么
- **诚实标注**：在 F 区明确标注假设和范围外内容
